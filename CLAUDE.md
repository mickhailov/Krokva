# Krokva — agent guide

Native **SwiftUI iOS** app for Canadian civic address dossiers ("Reports"), built from municipal open data. Currently ships Winnipeg. iOS 17+, Swift 5.9, light-mode only.

## Build & run
Project is generated by **XcodeGen** from `project.yml` — never hand-edit `Krokva.xcodeproj`.
```sh
xcodegen generate                                   # after adding/removing/moving files
xcodebuild -scheme Krokva -destination 'platform=iOS Simulator,name=iPhone 15' build
```
Add a new `.swift` file → it's picked up automatically (sources glob `Krokva/`), but run `xcodegen generate` to refresh the project.

## Conventions
- Design system is **Civic Modernist**: wrap content in `KrokvaCard` with an eyebrow label; use paper/surface tokens from `App/Branding/`. Details in memory `project-krokva-design.md`.
- Numeric model fields are **`Double`** (not Int/Float).
- The core flow is **`Features/Report/`** (`ReportView` / `ReportService` / `ReportModels` / `ReportRating`); each dossier card lives in `Report/Cards/`.
- Adding a Report card → create it in `Features/Report/Cards/`, insert into `ReportView`'s stack.
- Adding a city → implement `CityDataProvider`, register in `CityRegistry`.
- SwiftData models live in `Core/Cache/LocalModels.swift`; networking in `Core/Networking/`.
- **Empty vs error states**: distinguish the two. When a card's database/source loaded successfully but returned nothing for this address, render a "No data" label (`EmptyCardState`). When the fetch itself failed (network/DB error), render a "Database error" label. Never silently hide a card on error — only the loaded-but-empty case degrades quietly.

## Report coverage (Winnipeg)
Each address Report is assembled by `WinnipegProvider.fetchReport` as a parallel `async let` fan-out, one optional `*Summary` per module on `AddressReport`. A card renders nothing when its summary is nil/empty, so thin or rural addresses degrade gracefully. Modules:
- **Property** — assessment, tax estimate, facts, comparables, neighbourhood value bins, House Score.
- **Permits & development** — building / development / trade permits, vacant-building orders, planning notices, short-term rentals, bylaw investigations.
- **Safety & health** — WFPS emergency calls, public health (naloxone/substance use + WRHA ER wait times), police crime, **neighbourhood risk** (rooming-house enforcement, vacant-property fires, rush-hour towing, paid parking).
- **Daily living** — **waste & winter** (garbage/recycling/yard-waste day, plow zone + next plow window, active snow ban), **demographics** ("Who lives here": census age/income/household/commute/language/immigration + higher-poverty flag), **local government** (ward councillor + community committee via point-in-polygon), **local businesses** (licensed within 500 m + patios).
- **Amenities & street** — parks, recreation/leisure, **pools & amenities** (indoor/outdoor/wading/spray + walkways + public Wi-Fi), library, river gauge, transit, schools, street access (pavement, school speed, cycling, disruptions), **traffic** (midblock + permanent counters), **drinking water quality**, **capital projects** + **health-inspection closures** (street-matched).
- New civic-data modules live in `Report/Cards/CivicDataCards.swift`; dataset IDs + verified Socrata joins are in memory `feature-opendata-expansion.md`. Census joins on `boundary_name`; ward/committee/poverty are point-in-polygon (`intersects(the_geom/location, 'POINT(lon lat)')`); proximity modules use `within_circle`.
